Network Bridge 架构总览

一个跨平台的 C99 通信框架：ntk 提供运行时，之上是发现、传输、RPC/流；另有一条独立的 RTPS/DDS 协议栈，可和 Cyclone DDS 互通。细节见文末的专题文档。

1. 分层

应用node / service / proxy / stub / stream / publish
RPC 与消息核心dispatch、pending、dedup、reply、router、registry、waitset、envelope v2
服务发现独立库 ntk_discovery：UDP 广播 HELLO/BYE（不透明 key + value）+ 周期心跳 + 对端注册表
框架传输UDP（分片/乱序窗口/NACK/RTX/AIMD/可选 FEC）、TCP（长度前缀）、SHM（零拷贝）、Cyclone DDS 适配
RTPS / DDS独立协议栈：SPDP/SEDP、可靠传输、分片、QoS；公共 rtps_* 接口；可做框架的 rtps:// 传输
ntk 运行时跨平台 poller + 线程、定时器、同步原语、MPSC 队列、线程池、poller 负载

两条数据面是并行的：普通 RPC 走 UDP/TCP/SHM；需要和 DDS 世界互通时走 RTPS（或 Cyclone DDS 适配）。二者共用 ntk，互不依赖。

2. ntk：跨平台运行时

Network Tool Kit 等价于 DDS 里的 ddsrt：把 OS 差异收敛成一套 C 接口，框架和 RTPS 都只依赖它。

  • poller + 线程模型：每个 node 一个 poller 线程跑事件循环（epoll / kqueue / IOCP 封装）；回调和定时器默认都在 poller 线程执行，没有隐含线程。
  • 定时器：ntk_timer_start（周期/单次）和 ntk_poller_do_delay（一次性延迟），都挂在 poller 上，不额外起线程。
  • 负载计算：ntk_poller_get_load / ntk_poller_pool_get_loads 给出负载值，用于观测和 poller 池调度。
  • 耗时任务：ntk_thread_pool；阻塞 handler 通过 WORKER 模式或调用方 EXECUTOR 挪出 poller 线程。
  • 其余：mutex/sem/cond、线程、MPSC 队列、socket 封装、日志门面。

3. 发现：广播 + 心跳

服务发现是控制面，和数据面传输解耦：UDP 广播 HELLO/BYE，载荷是 key + value——节点 ID、服务名、以及每个 binding 的完整 URI（udp://、tcp://、shm://、rtps://、dds://）。

  • 周期心跳刷新 last_seen，超时即摘除对端及其服务；BYE 用于主动下线。
  • 结果写入 registry，proxy/stub 按 service.method 解析到具体 endpoint；支持显式单播 target 和静态路由。
  • RPC 与 SHM 的服务发现是同一套逻辑，区别只在 URI 的 scheme 和端点字段。

4. TCP / UDP 与 RPC

调用proxy / stub
→
信封envelope v2（magic/version/CRC）
→
传输UDP / TCP / SHM
→
分发dispatch → service
传输要点
UDP类 RTP 头（PT、序号、消息 ID）；分片/重组、乱序窗口；丢包用 NACK + 重传，拥塞用 AIMD；可选整包 XOR FEC（FEC=1，默认关）用一个校验包重建单个丢失分片，省掉一次往返
TCP长度前缀分帧，连接复用；跨网段、穿只允许长连接的场景
SHM共享段 + 每节点入站队列，chunk 引用计数做零拷贝；本机 RPC/事件优先走它

RPC 核心负责关联、超时、重试、去重和回复；传输只搬一个归一化的消息，不解析业务载荷。

5. RTPS / DDS 协议栈

src/rtps/ 是与框架传输并行的一套 RTPS 2.4 实现，自己的层次也和 Cyclone 对齐：

公共 APIinclude/rtps · rtps_*
→
引擎src/rtps · SPDP/SEDP/可靠/分片/QoS
→
运行时ntk
  • 发现：SPDP 组播 + SEDP 单播；端点 QoS 通告与 RxO 匹配。
  • 可靠性：writer 历史、HEARTBEAT/ACKNACK/GAP、晚加入者回放；分片 DATA_FRAG/HEARTBEAT_FRAG/NACK_FRAG。
  • API：participant → topic → writer/reader（含 publisher/subscriber 分组）、read/take/waitset、loan 视图、状态/发现/指标；接口层只依赖公共头，引擎头在 src/rtps/internal/。
  • 互通：与 Cyclone DDS 11 的 UDP 组播/单播双向互通已验证；TCP 只在本实现实例之间验证（Cyclone 的 TCP 模式会替换发现传输）。
  • 框架接入：rtps://<domain> 作为一个 transport provider，和 dds://（Cyclone）并列。
